# Member 数据访问与模型出境规则

> 本表仅适用于 PostgreSQL 的 `Member`。员工权限不再使用 `E0-E3` 分级；员工访问依据模块权限、编辑范围和“是否为归属顾问”三项规则裁决。

## 员工访问规则

| 场景 | P1 | P2 | P3 |
|---|---|---|---|
| 查看会员非身份资料 | 全部会员 | 全部会员 | 全部会员 |
| 查看手机号、身份证 | 仅归属自己会员原文，其他脱敏 | 仅所属门店会员原文，其他门店脱敏 | 全部会员原文 |
| 编辑普通会员资料 | 自己归属会员 | 本门店会员 | 全部会员 |
| 修改手机号、身份证 | 自己归属会员 | 本门店会员 | 全部会员 |

`storeId` 和 `ownerEmployeeId` 是数据范围依据，不是会员自身的权限信息。普通会员编辑接口不能修改 `storeId`。

## 加密存储

| 字段 | 存储方式 | 用途 |
|---|---|---|
| `phoneEncrypted` | AES-256-GCM 密文 | 按 P1/P2/P3 数据范围受控读取、联系 |
| `phoneHash` | HMAC-SHA256 摘要 | 精确检索、去重、黑名单判断 |
| `idCardEncrypted` | AES-256-GCM 密文 | 按 P1/P2/P3 数据范围受控身份核验 |
| `idCardHash` | HMAC-SHA256 摘要 | 精确检索、去重、风险判断 |

除以上四个字段外，`Member` 的姓名、生日、职业、收入、城市、家庭背景、介绍和择偶偏好均为明文业务字段，可用于受权限保护的 PostgreSQL 查询。

## 模型出境规则

模型不直接连接数据库。后端仅能通过 Business Tool 查询，再根据 Provider 裁剪结果：

| 模型等级 | 含义 | 典型字段 |
|---|---|---|
| M0 | 不提供给任何模型 | 手机号摘要、身份证摘要、审计字段、员工归属、证件原文 |
| M1 | 仅本地模型可用 | 姓名、完整手机号；手机号仍须先按当前员工的 P1/P2/P3 数据范围校验 |
| M2 | 本地和云端模型可用 | 性别、学历、职业、收入范围、城市、择偶偏好、匿名画像 |

云端模型永远不得获得姓名、完整手机号、身份证及其摘要；本地模型也只能获得通过当前员工权限校验后的必要数据。
