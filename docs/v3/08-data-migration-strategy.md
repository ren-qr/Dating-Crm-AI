# 数据迁移策略

## 原则

- 旧 CRM 保持可运行，迁移采用并行读、单向写与逐步切换。
- 不删除旧表、不执行破坏性迁移，直到新链路回归与业务验收通过。
- 所有新表必须拥有 up/down 迁移、索引、幂等键、审计字段和回滚方案。

## 迁移顺序

1. 盘点现有 `Member`、`MemberService`、`Employee`、`Store`、`AuditLog`、`AiSetting`。
2. 新增 Runtime 元数据表与 Outbox，不改现有会员写入路径。
3. 新增 `MatchCase`，以员工确认后的候选草案创建。
4. 双写仅用于短期受控迁移，设置对账任务与停止条件。
5. 切换读取方后保留回滚窗口，再删除废弃读取代码。

AI 配置的唯一持久来源为 `AiSetting`；环境变量只作为部署默认值或无数据库时的回退。V3 不再写入 `storage/ai-config.json`。
