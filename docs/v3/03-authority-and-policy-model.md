# 权力与策略模型

## 两级员工产品权限

V3 产品角色收敛为：

| 角色 | 会员数据 | 非会员管理 |
| --- | --- | --- |
| `Staff` | 查看、编辑全部会员业务字段 | 无门店、员工、系统策略管理权 |
| `Manager` | 继承 `Staff` 的全部会员能力 | 门店、员工、系统配置与政策审批 |

会员数据不按职级、会员归属或门店范围再次裁剪。只要拥有相应的 `member:*`、`profile:*` 能力码，两个角色都可对全部会员执行创建、读取、更新、删除和归属调整，并可读取手机号、身份证等会员字段。`Staff` 与 `Manager` 的会员相关能力码必须保持一致。

会员归属调整仍需满足数据完整性：归属员工必须为该会员所属门店的有效员工。这是记录关系校验，不是权限范围限制。

历史数据库角色代码会在登录时映射为 `Manager` 或 `Staff`；历史代码不再是 V3 的权限层级，也不得出现在 V3 的产品文案或策略判断中。

## Policy Engine 输入

```text
Subject：当前员工/会员、Agent 身份、委托来源
Action：member.read / member.write / match.create / meeting.manage ...
Resource：目标记录与所属范围
Fields：请求读取或写入的字段
Context：页面、Trigger、Case、审批、风险、模型提供方
```

输出为显式 `PolicyDecision`。Runtime 是第一道工具门禁，Tool/Domain Service 必须再次校验，返回数据前再裁剪字段，模型输出前最后检查敏感内容。

员工字段权限与模型数据投影分离：员工可获授权查看会员字段，不代表云端模型可接收姓名、电话、身份证或内部备注。手机号、身份证继续加密存储。
