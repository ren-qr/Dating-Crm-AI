## 2. 背景与目标

Meetra 最初是相亲机构后台管理网站，并带有面向内部工作人员的普通自然语言 AI 助手。未来方向是逐步演进为完整的 AI 员工 Agent，让 Agent 参与甚至替代员工的更多工作，并探索超出真人员工能力的自动化与智能化能力。

本版需求以产品负责人最新确认作为范围基线：首期只做内部员工管理，即后台管理。会员端前台、涉及会员直接交互的流程、线下流程、线下 AI 主持和智能硬件暂不纳入首期。

### 目标用户

- 内部员工：录入、查询、维护会员资料，记录跟进，处理黑名单和日常运营任务。
- 管理者：管理员工、门店、系统配置，查看运营看板，复核高风险操作。
- 运维/技术人员：部署、备份、恢复、监控和排查系统问题。
- 内部 Agent：作为系统组件，为员工提供后台查询、分析、草案和任务辅助；不默认等同于独立用户。

### 现有问题

- 当前 AI 助手只是普通聊天，不访问会员数据、不调用业务工具、不执行业务写操作。依据：`README.md` 和 `src/app/api/v1/ai/chat/route.ts`。
- 当前代码已有 CRM 基线，但 V3 目标中的 Runtime、Policy、Tool Registry、MatchCase、AgentTask 等仍是设计概念，未实现。依据：`docs/v3/00-v3-rebuild-overview.md`、`docs/v3/02-domain-model.md`。
- 后台管理已具备部分模块，但需求、权限、验收追踪需要统一文档化。

### 预期价值

- 让内部运营工作围绕会员、跟进、风险、员工、门店和看板形成可审查闭环。
- 为后续 AI 员工 Agent 建立可追踪的权限、审计、数据投影和验收基础。
- 避免把会员端、线下主持和硬件方向过早混入首期，降低范围失控风险。

### 成功指标

无已批准量化指标。本版只记录建议目标：

- 建议目标：后台核心流程能通过测试覆盖并在演示数据上完成端到端操作。
- 建议目标：关键写操作有审计记录，敏感字段不明文返回或落日志。
- 建议目标：AI 首期能力的每次业务工具调用均可追踪到操作者、权限决策和结果摘要。
- 待测量：后台页面响应时间、导出耗时、AI 成本、任务失败率、人工介入率。

## 3. 系统边界

### 当前范围

当前实现包含：

- 登录与会话：NextAuth Credentials。代码路径：`src/business-support/permissions/**`、`src/app/api/auth/[...nextauth]/route.ts`。
- 会员管理：列表、创建、详情、更新。代码路径：`src/app/api/v1/members/**`。
- 跟进记录：创建跟进并可生成提醒类服务记录。代码路径：`src/app/api/v1/followups/route.ts`。
- 黑名单：列表、新增、拦截部分高风险动作。代码路径：`src/app/api/v1/blacklists/route.ts`、`src/lib/server/blacklist.ts`。
- 员工、门店、审计、看板、AI 设置和普通 AI 聊天。
- Prisma/PostgreSQL 数据模型。代码路径：`prisma/schema.prisma`。

### 首期范围

首期只覆盖内部后台管理：

- 员工登录、权限与个人信息。
- 会员档案录入、查询、修改、状态维护。
- 会员跟进、提醒、服务记录。
- 黑名单风险管理与拦截。
- 员工、门店与系统设置管理。
- 运营看板。
- 内部 AI 助手作为 Staff Copilot 的后台辅助能力，优先支持自然语言询问、固定功能入口、查询解释、草案生成和报告辅助；是否允许业务写操作仍待确认。

### 后续方向

以下方向只作为后续候选，不进入首期验收：

- 智能匹配推荐的完整 MatchCase 流程。
- 会员端 AI 咨询和 Member Advisor。
- 双方意愿收集、约见协调、取消和改期。
- 线下 AI 主持、暖场、对话辅助、人工接管。
- 经授权的沟通记录、会后复盘。
- 麦克风、扬声器等智能硬件。

### 明确不做

首期不做：

- 会员端前台。
- 涉及会员直接参与的线上或线下流程。
- 实时语音、自动外联、自动约见。
- 模型直连数据库或执行 SQL。
- Agent 绕过权限、审批和审计直接写库。

## 4. 使用者与相关方

| 相关方 | 目标 | 职责与边界 |
| --- | --- | --- |
| Staff | 高效完成会员资料、跟进、风险处理等日常后台工作 | 可在权限范围内处理会员数据；V3 文档确认 Staff 与 Manager 对会员数据范围相同 |
| Manager | 管理员工、门店、系统配置和运营质量 | 管理非会员模块；是否包含模型配置、政策发布、费用配置仍待确认 |

| 内部 Agent | 辅助员工进行后台查询、分析、草案、报告和任务处理 | 系统组件；必须受 Tool Registry、Policy、审计和停止条件约束 |
| 会员 | 后续可能使用会员端服务 | 首期不作为系统直接使用者 |

## 5. 典型业务场景与用例

### UC-MEMBER-001 会员录入、查询、修改与跟进

- 参与者：Staff、Manager、系统。
- 触发条件：员工在后台录入新会员或维护现有会员。
- 前置条件：员工已登录，具备 `member:read`、`member:write`、必要时 `profile:*`、`followup:*` 权限。
- 正常流程：员工创建或查询会员；系统校验参数和权限；系统保存资料或返回列表/详情；员工记录跟进；系统生成审计记录。
- 异常流程：参数错误返回 1000；未登录返回 1001；无权限返回 1002；黑名单命中返回 1005；资源不存在返回 1003。
- 结果：会员资料、服务记录和审计记录可追踪。
- 权限约束：Staff 与 Manager 对会员数据范围相同是已确认 V3 决策；敏感字段展示和模型投影仍需安全复核。

### UC-AI-001 自然语言询问和固定功能入口

- 参与者：Staff、Manager、内部 Agent、系统。
- 触发条件：员工在后台输入自然语言，或点击固定功能入口。
- 前置条件：员工已登录；AI 能力已配置；业务工具权限已定义。
- 正常流程：系统识别输入来源；固定入口直接映射功能；自然语言请求经语义路由或澄清；系统执行允许的查询、分析或草案生成；结果返回员工确认。
- 异常流程：请求不明确时要求澄清；无权限时拒绝；模型不可用时返回可理解错误；工具失败时记录失败并提示人工处理。
- 结果：员工获得查询结果、说明、草案或下一步建议。
- 权限约束：当前实现的 AI chat 不读会员库、不调用业务工具；AI 业务工具是否进入首期仍为阻塞项 OD-001。

### UC-RISK-001 黑名单管理与高风险拦截

- 参与者：Staff、Manager、系统。
- 触发条件：员工新增黑名单，或创建/更新会员、跟进等操作触发风险检查。
- 前置条件：员工已登录并具备 `blacklist:*` 或相关业务权限。
- 正常流程：员工登记黑名单原因、严重级别和关联对象；系统保存风险记录；业务操作前检查有效黑名单；命中则阻断并写审计。
- 异常流程：目标会员不存在；黑名单依据不足；无权限；重复或过期记录处理规则待确认。
- 结果：风险记录可查询，高风险动作被拦截。
- 权限约束：黑名单原因可能包含敏感内容，对外和模型投影应默认受限。

### UC-OPS-001 定时报告和异常任务处理

- 参与者：Manager、运维/技术人员、内部 Agent、系统。
- 触发条件：定时任务或管理者手动触发运营报告。
- 前置条件：报表范围、权限、数据来源、失败重试策略已配置。
- 正常流程：系统按时间范围汇总会员新增、跟进待办、黑名单、看板指标；Agent 生成摘要草案；Manager 查看并确认。
- 异常流程：数据源不可用、任务超时、权限不足、报告生成失败；系统应保留失败状态和错误摘要。
- 结果：报告可追踪、可复核、可重试。
- 权限约束：报告不得泄露无关门店或未授权敏感字段；具体门店隔离策略需复核。

### 候选用例，首期不承诺实现

以下用例暂不进入首期，只为后续保留追踪位置：

- UC-MATCH-001 匹配推荐与意愿收集。
- UC-MEETING-001 约见协调、取消、改期。
- UC-HOST-001 线下主持及人工接管。
- UC-REVIEW-001 会后反馈与复盘。

## 7. 数据需求

### 需要记录的业务事实

- 登录账号：员工身份、门店、角色、权限、状态、密码哈希和最后登录时间。当前模型：`Employee`、`Role`、`Permission`、`StaffRole`。
- 会员档案：会员编号、姓名、性别、生日、状态、来源、归属员工、联系方式和身份字段。当前模型：`Member`。
- 会员画像：身高、体重、学历、职业、收入范围、婚史、城市、家庭背景、自我描述、择偶偏好。当前模型：`Member` 与 `MemberProfile` 并存。
- 当前状态与历史：会员当前状态保存在 `Member.status`；跟进、黑名单、提醒、审计等历史事实独立记录。
- 业务事实与 AI 推断：AI 生成的建议、摘要、匹配理由不得默认等同于业务事实；正式事实必须由员工确认或由受控 Workflow 写入。
- 业务状态与系统执行状态：会员状态、黑名单状态是业务状态；AgentRun、WorkflowRun、ToolCall、PolicyDecision 等是未来系统执行状态，不应混写。
- 原始记录与分析结果：原始跟进内容、黑名单原因、审计摘要应与 AI 分析结果区分保存。

### 数据来源、归属和修改责任

| 数据 | 来源 | 归属 | 修改责任 |
| --- | --- | --- | --- |
| 员工账号 | Manager 或初始化 seed | 门店/系统 | Manager |
| 会员档案 | 员工后台录入 | 会员所属门店 | Staff/Manager |
| 跟进记录 | 员工后台填写 | 会员所属门店 | 记录人；更正规则待确认 |
| 黑名单 | 员工后台登记 | 门店/系统 | Staff/Manager；复核规则待确认 |
| 审计日志 | 系统生成 | 系统 | 不允许普通业务编辑 |
| AI 输出 | 模型生成 | 触发任务/会话 | 默认草案；确认后才进入业务记录 |

### 数据保留

无已批准保留期限。本版要求：

- 审计日志、黑名单、会员资料修改历史的保留期限 TBD。
- AI 交互日志、工具调用摘要和模型输入投影的保留期限 TBD。
- 不得在报告中虚构保留天数或删除周期。

## 8. 业务规则与权力边界

- Staff 与 Manager 对会员数据拥有相同能力和数据范围；差异在门店、员工、系统设置等非会员模块。依据：`docs/v3/10-open-decisions.md`。
- 业务接口默认需要登录；通过角色和权限码做二级授权。依据：AGENTS 和现有 `requireCurrentEmployee`、`requirePermission`。
- 模型不得直连数据库或执行 SQL。依据：`docs/v3/01-product-boundary.md`、`docs/v3/04-agent-workflow-tool-boundary.md`。
- 员工可见会员字段不代表云端模型可接收这些字段。依据：`docs/v3/03-authority-and-policy-model.md`。
- 黑名单命中后必须阻断高风险动作并记录审计。依据：AGENTS 和当前代码。
- AI 建议、模型推断和草案不得冒充会员明确意愿或正式业务结论。
- Manager 的模型配置、政策发布、费用与门店创建权限仍待确认，见 OD-003。
- 首期不处理会员明确意愿、约见确认、取消改期、录音转写和线下接管规则。

## 9. 非功能需求

| 类别 | 需求 |
| --- | --- |
| 性能 | 后台高频表格和筛选应支持门店运营使用；具体响应时间和并发量待测量。 |
| 可靠性 | 关键写操作应具备参数校验、事务一致性和可恢复审计线索。 |
| 安全 | 所有业务接口默认认证；敏感字段不得明文落日志；权限码必须前后端一致。 |
| 隐私 | 电话、身份证等敏感字段应加密或哈希辅助检索；模型输入需按最小投影治理。 |
| 可恢复性 | 数据库迁移必须可回滚；备份与恢复能力应进入运维验收。 |
| 可维护性 | 需求、接口、测试和代码应可追踪；避免重复维护多份相同需求。 |
| 可观测性 | 审计日志、请求 ID、AI 工具调用和失败任务应可追踪。 |
| 成本 | AI 模型调用成本、任务失败重试成本和报表/导出成本待测量。 |

## 10. 智能硬件与现场环境需求

首期不纳入智能硬件、线下主持和现场环境能力。以下只作为后续方向占位，不进入首期设计或验收：

- 使用环境、距离、噪声、多人同时讲话。
- 供电、网络、安装和操作方式。
- 收音、播放、打断、静音、停止和人工接管。
- 断网、断电和设备故障。
- 录音提示、授权和保留期限。
- 软件与设备接口、版本兼容。
- 现成设备或自研方案选择。

后续若重新纳入，需要先形成独立现场需求和隐私授权方案，不提前指定芯片、开发板或供应商。

## 11. AI 质量与评测需求

首期 AI 评测只覆盖内部后台辅助；会员端、语音识别、线下主持暂不评测。

### 需评估任务

- 后台自然语言理解：能否识别查询、总结、草案、报告等意图。
- 工具选择：若启用业务工具，是否选择正确工具并提供合法参数。
- 查询解释：是否准确解释会员列表、跟进、黑名单、看板等结果。
- 推荐解释：仅作为后续候选，首期不验收。
- 报告生成：是否忠实基于系统数据，不编造指标。
- 失败处理：权限不足、数据不存在、模型不可用时是否给出可操作反馈。

### 评价方式

- 使用人工编写的后台任务样本集。
- 每个样本包含输入、期望工具、期望权限结果、允许输出范围和禁止输出内容。
- 人工复核必须参与验收；不得把另一个模型打分作为唯一依据。
- 不得把模型推测的情绪、意愿或风险判断当作确定事实。
